# Readshot v0.7.3

## Fixes

- Overlay: custom macOS crosshair cursor before dragging, avoiding the old canvas-redrawn cursor lag while still removing the system pointer beside it.
- Overlay: selector animation no longer redraws every full-screen overlay while the user is still choosing the initial region; the static dim veil is cached and drag redraws skip live text layout.
- Menu bar: History and Settings clicks no longer get swallowed by the same tray-icon click that can start Capture, and newly opened windows explicitly focus.
- Shortcuts: the advertised History and Settings shortcuts are registered globally, with focused-window fallbacks for Readshot windows.
- Capture: macOS region crops now use the actual image scale returned by ScreenCaptureKit, preventing shifted or clipped captures on displays whose returned backing scale differs from the expected display scale.
- App launch: reopening Readshot after Quit shows the ready window instead of silently returning to a menu-bar-only state.
- App launch: reopening an already-running menu-bar copy from Finder now opens/focuses the ready window instead of doing nothing.
- Settings: scrollbar placement and optical padding now match the History window.
- Release checks: local release validation now rejects stale tags that do not point at `HEAD`.

## Improvements

- Editor and tray polish: clearer tray Capture command, tighter shortcut coverage, safer editor cursor behavior, and UI refinements.
- CLI/MCP parity: CLI capture rejects extreme rectangles and scale values before rendering.
- History reliability: concurrent saves keep every index entry and atomic writes no longer reuse the same temp file path.
- CI hygiene: scheduled integration runs are wired up and no longer claim Screen Recording permission before it is actually granted.
- Dependency hygiene: test fixtures are kept behind test-only feature gates instead of shipping through normal capture/OCR dependencies.
